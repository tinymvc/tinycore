# Spark-Native Feature Map

Read this reference when a task touches a framework service beyond the ordinary route/request/model/resource path. It maps common core services and optional integrations across **TinyMVC / Spark** (implemented by the **TinyCore** engine). Confirm exact signatures in `vendor/tinymvc/tinycore/src` using `php vendor/tinymvc/tinycore/skills/tinymvc-spark/scripts/api-lookup.php <term>`.

## Cross-cutting rules

- Use dependency injection in reusable services and jobs when it makes the dependency visible; use a facade or global helper when that is the established application style.
- Keep request-specific identity, locale, tenant, and authorization in the current call. Do not store them in a singleton, static property, cache key omitted from a query, or serialized job accidentally.
- Do not create a service layer or repository for a one-line operation. Do create a service to coordinate multiple models, a database transaction, cache/storage, external HTTP/mail, or retry/idempotency policy.
- Do not swallow framework exceptions or turn a failed process, validation, authorization, transaction, queue, storage, or HTTP call into a success response.
- When in doubt about exact method signatures, run `php vendor/tinymvc/tinycore/skills/tinymvc-spark/scripts/api-lookup.php <term>` to inspect the installed runtime declarations directly.
